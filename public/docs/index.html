HubSpot Productboard Integration v1.0.22

Keep your Productboard account data in sync with HubSpot — automatically surface customer segments, deal values, and account details without leaving your product tool.

Overview

This integration pulls company data from HubSpot and pushes it into Productboard so your product teams always have accurate customer context when triaging feedback and planning roadmaps.

What gets synced

HubSpot objectProductboard objectDirection
CompanyCompanyHubSpot → Productboard
Company propertiesCustom fieldsHubSpot → Productboard (configurable)
ℹ
One-way sync Data flows from HubSpot into Productboard only. Changes made to companies inside Productboard are not written back to HubSpot.

Key behaviours

  • Idempotent: Running the same sync twice never creates duplicates. The engine matches on HubSpot company ID.
  • Incremental: Only records that have changed since the last successful sync are re-processed by default.
  • Dry-run safe: Set DRY_RUN=true in the environment to preview all writes without touching any API.
  • Rate-limit aware: A token-bucket limiter automatically throttles requests to stay inside Productboard (300 req/min) and HubSpot (100 req/10 s) limits.

Setup walkthrough

Getting from zero to your first sync takes about five minutes.

1
Sign in Open the app and click Sign in with Google. Use your company Google Workspace account — personal Gmail addresses are not permitted.
2
Connect Productboard Go to the Connect tab. Paste your Productboard API token and click Connect. The app will confirm your workspace name.
3
Connect HubSpot Still on the Connect tab, paste your HubSpot service key token and click Connect. The portal ID and hub name will appear when the token is valid, along with a per-scope check confirming each required scope is granted.
4
Filter which accounts to sync (optional) Open Filter accounts to narrow down which HubSpot companies are included. You can filter by property value, lifecycle stage, owner, or any HubSpot company property. Skip this step to sync all companies.
5
Map fields Open Map fields to choose which HubSpot company properties map to which Productboard company fields. At minimum, map Company name. Unmapped properties are ignored.
6
Schedule or run manually Open Schedule to set up automatic syncs (daily, hourly, etc.), or click Sync now on the same tab for a one-time run. Watch live progress in the status panel.

Connect accounts

Productboard API token

To generate a Productboard API token:

  1. In Productboard, go to Settings → Integrations → Public API.
  2. Click Add New Public API Token. Give it a descriptive name like HubSpot sync.
  3. Copy the token immediately — it is shown only once.
ℹ
The Productboard API token is scoped to the user who generated it. If that user is deactivated, the token stops working. Use a service account if your organisation has one. The token is encrypted and stored as a Secret Manager version (productboard-token) — never written to Firestore or the browser.

HubSpot service key token

To create a HubSpot service key (requires Super Admin or Developer tools permission):

  1. In HubSpot, go to Development → Keys → Service Keys and click Create service key.
  2. Name it (e.g., pb-hubspot-sync).
  3. Click Add new scope and enable all three: crm.objects.companies.read, crm.schemas.companies.read, and crm.objects.owners.read (the last one is needed to resolve HubSpot owner IDs to emails when mapping to Productboard member fields).
  4. Click Create and confirm, then copy the generated token.
ℹ
The Connect tab probes each scope when you save the token and on every Test connection run, and reports per-scope status (✓ granted / ✗ missing). The HubSpot token is encrypted and stored as a Secret Manager version (hubspot-token).

Filter accounts

By default the sync processes every company in your HubSpot portal. Use filters to limit scope — useful for large portals or when you only want to sync a specific customer segment (e.g., only Enterprise accounts with an active deal).

Operators by property type

Available operators are filtered to match the type of the HubSpot property you pick.

ℹ

Map fields

Field mapping controls which HubSpot company properties are written into which Productboard fields. Any HubSpot property that exists in your portal can be mapped.

Locked mappings

name and domain are locked — they always sync and cannot be disabled. The HubSpot company ID is also written to Productboard as the integration source ID (metadata.source.recordId) automatically and is used for deduplication on every subsequent run.

Custom field mappings

Any HubSpot company property (built-in or custom) can be mapped to a Productboard company field. The Map fields tab pairs HubSpot properties (left) with Productboard fields (right) via dropdowns. Available pairings are filtered by type compatibility, and a ⚠ Type mismatch badge appears if an old config contains an incompatible pair.

Schedule syncs

Scheduled syncs run automatically in the background using Google Cloud Scheduler. You do not need to keep the browser open.

ℹ
For Daily and Weekly, you also pick the time-of-day and a timezone (default America/New_York). The Schedule tab shows the next scheduled fire time as an absolute timestamp in your browser timezone plus a relative countdown.
⚠
Scheduled runs are incremental Scheduled syncs only re-process companies modified since the previous successful run (delta sync). Manual Sync now runs always do a full sweep, regardless of the last-modified window.

Manual sync

Click Sync now on the Schedule tab to run a one-off sync at any time. A live progress card streams via Server-Sent Events and shows fetched, created, updated, skipped, and error counts in real time. Click Cancel in the card to stop after the current batch finishes.

Sync history

The History tab shows every sync run with start time, trigger, duration, stats, and status. Filter by date range (7 / 30 / 90 days / all time), status, and trigger (Manual vs Scheduled). Click any row to expand per-record errors and, if Debug logging is enabled, the attempted Productboard payload and full API error response.

Rate limits

APILimitHow we handle it
Productboard 300 requests / minute The engine reads the remaining-quota headers HubSpot and Productboard return on each response and self-throttles before the bucket runs out.
HubSpot (free) 100 requests / 10 s Detected automatically from the X-HubSpot-RateLimit-* response headers — no manual tier setting required.
HubSpot (paid) 150 requests / 10 s Same auto-detection. Higher tiers will be picked up the moment HubSpot reports the larger bucket.

If a sync errors with 429 Too Many Requests, the engine retries with exponential backoff. You should not need to intervene. To soften load on a very large portal, lower the SYNC_CONCURRENCY environment variable on the Cloud Run service (default 5; range 1–25).

Troubleshooting

Authentication errors

ErrorLikely causeFix
401 Unauthorized (Productboard) API key is invalid or was rotated. Re-paste your Productboard API key in the Connect tab and click Verify.
401 Unauthorized (HubSpot) Service key token rotated, deleted, or scopes changed. Generate a new service key in HubSpot under Development → Keys → Service Keys and re-enter it in the Connect tab.
Sign-in blocked Your Google account is not on the allowed domain. Use your @yourcompany.com Google Workspace account.

Sync errors

ErrorLikely causeFix
Company not appearing in Productboard Company was filtered out, or the sync hasn't run yet. Check your filter rules in Filter accounts. Run a manual sync from Schedule.
Custom field value not syncing Field not mapped, or the Productboard custom field doesn't exist. Verify the mapping in Map fields. Confirm the custom field exists in Productboard settings.
429 Too Many Requests Rate limit hit — usually only on very large portals. The engine retries automatically with exponential backoff. If it persists, reduce the SYNC_CONCURRENCY environment variable on the Cloud Run service (default 5) and redeploy.
Partial sync — some records failed Individual company records contain unexpected field values. Download the history CSV from the History tab and review the error column for specific record IDs.

Scheduled sync not running

  1. Open the Schedule tab and confirm the cadence is set to something other than Manual only. The blue "Scheduled run set" banner at the top shows the next fire time — if it's missing, no schedule is active.
  2. Check the History tab for the expected run time. Cloud Scheduler may have a few minutes of jitter, and the Trigger column should show scheduler for an automated run.
  3. If a row appears with status Skipped, expand it — the skip reason will explain (most often "HubSpot or Productboard not connected"). Reconnect on the Connect tab and the next tick will run.
  4. If no entry appears at all 15 minutes past the scheduled time, check the Cloud Scheduler console in GCP and the Cloud Run logs for the OIDC verification error.

FAQ

Can I sync data the other way — from Productboard back to HubSpot?

Not currently. The integration is HubSpot → Productboard only. Reverse sync (e.g., writing Productboard feature votes back to HubSpot deals) is on the roadmap.

Will the sync overwrite data I've manually entered in Productboard?

Yes, for any field that has an active mapping. If you map HubSpot's Industry to a Productboard custom field, any manual edits to that field in Productboard will be overwritten on the next sync. Only map fields where HubSpot is the system of record.

How are duplicate companies handled?

The engine matches on HubSpot company ID, stored as metadata.source.recordId on the Productboard entity. If a Productboard company already has this source ID, it is updated rather than re-created. When the source ID is missing (e.g. for a record created in PB before the integration was wired up), the engine falls back to a case-insensitive domain match on the domain field — and on a successful fallback, writes the HubSpot ID back so subsequent runs use the fast primary path. Domain fallback can be turned off in the Settings tab.

What happens if I delete a company in HubSpot?

Deleted HubSpot companies are not automatically removed from Productboard. The integration only creates and updates — it does not delete. You'll need to archive the company manually in Productboard.

Can I run this locally without a GCP project?

Yes. Set FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 and FIRESTORE_PROJECT_ID=demo-local in your .env file, then run npm run dev. Scheduled syncs require Cloud Scheduler and won't work locally, but you can trigger syncs manually from the UI.

How do I grant another team member access?

Access is controlled by Google OAuth — any user in your allowed Google Workspace domain can sign in. To restrict to specific addresses, set GOOGLE_ALLOWED_EMAILS in your environment. Ask your infrastructure team to update the environment variable and redeploy.

Where are my API keys stored?

In production, the HubSpot and Productboard tokens you paste into the Connect tab are written to Google Cloud Secret Manager as hubspot-token and productboard-token versions. Only the version resource name (e.g. projects/.../secrets/hubspot-token/versions/1) is stored in Firestore — the raw token never returns to the browser, and the GET /api/connections response only includes a masked preview. In local development against the Firestore emulator, the Secret Manager call short-circuits and the value lives in emulator state on your machine.

Why does my last sync show as "Skipped" with a reason?

A sync skips when one of the connections is missing — for example, the HubSpot or Productboard token was disconnected, or the Cloud Run instance restarted before the Connect-tab tokens were re-resolved. The History row's expanded view shows the reason. As soon as you reconnect both systems on the Connect tab, the next scheduled (or manual) run resumes normally.
